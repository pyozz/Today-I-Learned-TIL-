리액트를 사용하면서 가장 흔하게 마주치는 상황 중 하나는 바로 상태(State)를 변경하는 것입니다. 그런데 코드를 작성하다 보면 현재의 상태 값을 그대로 가지고 업데이트를 하려다가 예상치 못한 버그를 마주하거나, 여러 번의 업데이트 중 일부가 무시되는 현상을 겪을 수 있습니다.

리액트에서 **이전 상태(Previous State)를 기반으로 안전하게 상태를 업데이트하는 방법**과 그 이유인 **배칭(Batching)**, 그리고 리액트의 **스케줄링** 동작 원리에 대해 알아보겠습니다.\*\*\*

<br />

### 왜 현재 상태 변수를 직접 쓰면 안 될까?

리액트에서 카운터를 1씩 증가시키는 버튼을 만든다고 가정해보겠습니다. 한 번 클릭했을 때 값을 3번 연속으로 올리고 싶어 아래와 같이 코드를 작성했습니다.

```javascript
onst[(count, setCount)] = useState(0);

const handleTripleIncrement = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
};
```

버튼을 클릭하면 count가 3만큼 증가할 것 같지만, 실제로는 **단 1만 증가합니다.**

그 이유는 리액트 컴포넌트 안에서 상태 변수(count)는 **특정 렌더링 시점의 고정된 값(스냅샷)을 바라보고 있기 때문**입니다. 함수가 실행되는 시점에 count가 0이었다면, 세 줄의 코드 모두 0 + 1을 실행하게 됩니다. 결국 setCount(1)이 세 번 호출되는 셈이므로 결과는 항상 1이 됩니다.

<br />

### 함수형 업데이트

이 문제를 해결하기 위해 리액트는 상태 변경 함수(Setter)에 직접 값을 넣는 대신, **이전 상태를 매개변수로 받는 콜백 함수(함수형 업데이트)를 전달**할 수 있는 기능을 제공합니다.

```javascript
const handleTripleIncrement = () => {
  setCount((prevCount) => prevCount + 1);
  setCount((prevCount) => prevCount + 1);
  setCount((prevCount) => prevCount + 1);
};
```

이렇게 작성하면 리액트는 이전 업데이트가 반환한 최신 상태(prevCount)를 다음 업데이트 함수의 인자로 차례대로 넘겨줍니다. 그 결과 원하는 대로 값이 3만큼 안전하게 증가하게 됩니다.

<br />

### 배칭(Batching)과 스케줄링

이런 방식을 활용해야 하는 이유는 리액트의 **배칭(Batching)과 스케줄링(Scheduling)** 메커니즘 때문입니다.

#### 배칭(Batching - 일괄처리)

리액트는 성능 최적화를 위해 **여러 개의 상태 업데이트를 모아서 한 번의 렌더링으로 처리**합니다.

- 만약 버튼 클릭 하나에 setName, setAge, setAddress 등 수많은 상태가 각각 따로 렌더링을 유발한다면 **브라우저는 엄청난 부하**를 겪을 것입니다.
- 리액트는 이벤트 핸들러 안에서 발생하는 여러 상태 업데이트를 **하나의 그룹(Batch)으로 묶어서** 마지막에 단 한 번만 컴포넌트를 리렌더링합니다.
- 이 과정에서 상태 업데이트 요청들은 큐(Queue)에 쌓이게 되는데, 직접 변수를 참조하면 큐에 쌓이기 전의 낡은 값을 바라보게 되는 문제가 생깁니다.

#### 스케줄링(Scheduling - 비동기 처리)

리액트의 상태 업데이트는 즉시(Synchronous) 일어나지 않고, 리액트 내부의 스케줄러에 의해 비동기적으로 처리됩니다.

- 특히 setTimeout, Promise, 또는 DOM 이벤트 리스너 내부 등 리액트의 제어 바깥(또는 특정 비동기 시점)에서 상태를 바꿀 때 스케줄링 타이밍에 따라 최신 상태를 놓치기 쉽습니다.
- 함수형 업데이트를 사용하면, 리액트가 스케줄링된 작업들을 순차적으로 처리할 때 "가장 최신의 이전 상태"를 보장하여 계산할 수 있도록 안전장치를 제공하는 것입니다.

이를 간단하게 표현하면 다음과 같습니다.

```
setState()
↓
상태 업데이트 요청
↓
React가 업데이트를 스케줄링
↓
업데이트 처리
↓
컴포넌트 다시 실행
↓
새로운 state 값
↓
JSX 다시 계산
↓
화면 업데이트
```

따라서 setCount()를 호출한 직후에는 현재 렌더링에서 사용하고 있던 count 값이 그대로입니다.
