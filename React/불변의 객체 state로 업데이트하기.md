리액트를 사용하다 보면 상태(State)가 객체나 배열인 경우를 흔히 마주합니다. 이때 기존 상태를 직접 수정하는 방식 대신, 불변성(Immutability)을 지켜가며 업데이트해야 합니다. 불변성을 지킨다는 것은 기존의 객체나 배열을 직접 변경하지 않고, 그 복사본을 만들어 수정한 뒤 새로운 상태로 교체하는 것을 의미합니다.

자바스크립트에서 객체와 배열은 원시 타입과 달리 참조값(Reference)으로 동작합니다. 메모리 주소를 참조하고 있기 때문에, 원본 데이터를 직접 조작하면 메모리 상의 실제 값이 곧바로 바뀌어버립니다.

예를 들어 2차원 배열 상태를 다룰 때 다음과 같은 코드를 작성하기 쉽습니다.

```javascript
setGameBoard((prevGameBoard) => {
  prevGameBoard[rowIndex][colIndex] = "X";

  return prevGameBoard;
});
```

이처럼 prev[rowIndex][colIndex] = "x"와 같은 방식은 메모리 속의 기존 값을 그 자리에서 바로 변경해버립니다. <br />
이 시점은 리액트가 비동기로 처리하는 예정된 상태 업데이트보다 이전에 발생합니다.

즉, 리액트가 변경을 감지하기도 전에 원본 데이터가 이미 훼손되어 버리기 때문에, <br />
컴포넌트가 올바르게 리렌더링되지 않거나 이전 상태와 현재 상태를 정확히 비교하지 못하는 알 수 없는 버그가 발생할 수 있습니다.

<br />

### 불변성을 지키는 올바른 업데이트 방법

원본을 유지하면서 안전하게 상태를 바꾸려면 스프레드 연산자 등을 활용해 새로운 참조를 가진 복사본을 만들어야 합니다.

```javascript
setGameBoard((prevGameBoard) => {
  const updatedGameBoard = [
    ...prevGameBoard.map((innerArray) => [...innerArray]),
  ];
  updatedGameBoard[rowIndex][colIndex] = "X";

  return updatedGameBoard;
});
```

이 방식을 사용하면 기존의 prevGameBoard는 전혀 수정되지 않고, 수정된 행과 셀만 새로운 객체/배열로 재생성됩니다. 자바스크립트는 새로운 메모리 주소를 바라보게 되므로 리액트는 상태가 변경되었음을 정확히 인지하고 리렌더링을 안전하게 수행합니다.

<br />

### 불변성 유지가 가져다주는 이점

- **예측 가능한 상태 관리** <br /> 참조값이 바뀌지 않은 채 내부 데이터만 몰래 바뀌는 일이 없어지므로 디버깅이 쉬워집니다. <br />
- **정확한 렌더링 최적화** <br /> 리액트는 얕은 비교(Shallow Compare)를 통해 상태 변경을 감지하므로, 새로운 객체나 배열을 생성해 전달해야만 변경 사항을 올바르게 포착할 수 있습니다.

- **사이드 이펙트 방지** <br /> 원본 데이터의 예기치 않은 변형을 막아 컴포넌트 간 데이터 흐름이 안전해집니다.
